# SceneLab v1.4

光学动捕相机部署与理论精度仿真工作台。**v1.4 新增 Auto Deploy 自动部署**：按约束生成候选，复用物理仿真引擎精算，预览、比较并应用为可编辑方案。支持 Windows、Apple Silicon 与 Intel Mac；Kimi 助手为可选功能，离线规划无需 API。

[下载 v1.4.0](https://github.com/deathunt1-blip/SceneLab/releases/tag/v1.4.0) · [自动部署使用说明](docs/AUTO_DEPLOY.md) · [更新记录](CHANGELOG.md) · [版本管理与发布流程](docs/VERSIONING.md)

## 分发版

### macOS

macOS **13 Ventura 或更新版本**：M 系列芯片选 `arm64`，Intel 选 `x64`。打开 DMG，将 SceneLab 拖到 Applications 后，从“应用程序”打开；ZIP 需完整解压，保留整个 `.app`。无需 Node.js，菜单“帮助 → 使用说明”可打开内置离线 HTML 手册。

Mac 版使用 ad-hoc 签名，未使用 Apple 开发者证书，未公证。首次打开如被阻止，在“系统设置 → 隐私与安全性”按提示选择“仍要打开”；参见 [Apple 说明](https://support.apple.com/zh-cn/guide/mac-help/mh40616/mac)。企业策略限制时需 IT 处理。

复制、粘贴、撤销等使用 ⌘ 键。关闭窗口后可点击 Dock 图标恢复，⌘Q 完全退出。数据位于 `~/Library/Application Support/Camera Planner`；Windows 与 Mac 通过项目文件及参数库 JSON 迁移，报告包格式不变。详细安装和操作步骤见 [Mac 使用说明](docs/macOS-使用说明.html)。

### Windows

发布文件位于 `release/SceneLab-v1.4/`。同事可运行安装程序，或完整解压免安装 ZIP 后双击 `SceneLab.exe`；不需要 Node.js。程序同目录有「使用说明.pdf」，应用内按 F1 打开。

安装版与免安装版都使用当前用户的 `%APPDATA%\\Camera Planner`，以兼容已有项目。免安装是无需安装，不表示数据随程序目录移动。分享项目和自定义相机库时，分别导出项目文件与参数库 JSON。发布包不包含本机用户数据。

本版未数字签名，未提供自动升级。企业设备受限时请交由 IT 审核。

## 源码启动

依赖已经安装、生产版本已经构建的本机，可双击根目录的 **启动 Camera Planner.vbs**。

从源码启动需要 Node.js 22.12+（分发版不需要）：

```powershell
npm ci
npm run desktop
```

开发模式：

```powershell
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。桌面版使用固定本地地址 `http://127.0.0.1:5178`，两者的存储相互独立；通过导出/打开项目和导入/导出参数库交换数据。程序与字体不依赖在线服务。

## 五分钟试用

1. 默认打开 12 × 10 × 5 m 演示场景：16 台相机、矩形桁架、平台、立柱和一个 Marker。
2. 打开右上角「相机参数库」，新建 ABC-400。基础模式通过分辨率与 FOV 推导内参；标定模式可直接录入内参和 Brown–Conrady 畸变。
3. 点击「阵列部署」，选择型号、数量、形状、高度与朝向。阵列生成后每台相机可独立编辑。
4. 选择相机，修改 XYZ / Yaw / Pitch / Roll，或使用三维操作手柄。右侧可以查看该相机的成像预览。
5. 添加方体、圆柱、墙、Marker 或四点刚体；也可多选至少三个 Marker 建立刚体。
6. 点击「运行分析」，切换覆盖数量与定位精度。拖动高度裁切查看不同高度，点击三维空间或问题条目查看逐相机诊断。
7. 点击「技术报告」，自动生成部署、俯视、前视、侧视、覆盖及精度截图。可独立切换报告语言，使用「打印 / 保存 PDF」在系统打印窗口保存 PDF。
8. 顶部导出项目。相机参数库另行导出 JSON / CSV 备份。

预置 **M4 · Demo 为合成演示参数，不代表任何厂商真实产品**。真实项目需录入经过确认的相机参数。示例名称 ABC-400 同样不代表真实产品规格。

## 青瞳相机数据库

已接入用户提供的《青瞳相机数据库标准数据表_V1.0.xlsx》：18 个型号、29 套光学配置、5 套 R3 帧模式。应用启动时一次性加入相机库，保留现有型号和项目快照；后续修改、删除不会被再次导入覆盖。相机库内按 CHINGMU 筛选，不同镜头与 R3 分辨率模式分别列出。

- 默认使用被动 Marker 距离；同时有主动距离的型号可在参数库切换。R3 的 ≥20 m 暂以 20 m 为保守仿真上限，原始限定符保留。U 系列使用表内水下有效 FOV 和未分类追踪距离。
- R1 为参考视频相机，不参与 Marker 求解，未知追踪距离保留为空。R3 可以参与求解，新部署时默认关闭，可在场景中启用。
- 原表缺失的图像点误差、最小像素阈值、最近距离与畸变采用可编辑的仿真假设（0.1 px、4 px、0 m 不限制、无畸变），不是厂商标定数据；厂商三维精度不会被当作像素误差。水体散射、浑浊和折射变化不在当前模型内。
- 每套配置保留完整相机、光学及对应帧模式的原始字段、空值、来源和备注，随 JSON / CSV 备份保存。源表及字段字典的无损提取位于 `src/camera/data/chingmu-v1.json`，带源文件 SHA-256。
- 新建或编辑后，点击底部固定的「保存型号」。保存状态在弹窗内显示；存储失败时保留草稿并提示导出备份。

## 已实现

### v1.4 自动部署

- 独立规划窗口：配置场地、Marker、精度、覆盖、型号、数量、安装、层数、中心权重及活动高度。
- 模板候选、粗筛、局部优化、数量细化与正式仿真，全部在 Worker 中执行，可取消。复用既有仿真模型；缓存重复的实体坐标变换，保持原计算数值。
- 多目标推荐、最佳尝试、真实诊断和放宽条件试验；全场统计不受优化权重影响。
- 临时三维相机及热图预览，应用为新方案 / 替换 / 追加，支持分组与一次撤销。
- 桌面 Kimi 可选：自然语言先转换为校验过的条件草稿，解释只整理验证过的事实。密钥由系统加密，默认为关闭状态，不随分发包共享。使用详见 [自动部署说明](docs/AUTO_DEPLOY.md)。

### v1.3 技术报告包

技术报告页新增「导出技术报告包」，与 PDF 打印并列。输出 `.scenelab-report` ZIP，默认包含 `manifest.json`、当前方案 `project.json`、`analysis.json` 摘要，以及部署、覆盖、精度六张 PNG；不包含 PDF、完整体素数组或其他方案。自定义相机和双目完整参数快照随包保存，不依赖官方产品 ID。

可选导出各相机二维视图和内部诊断，默认均关闭。双目分别输出左右目；图片复用报告概览，原始传感器像素坐标和 Marker 投影尺寸写入 `camera_views/index.json`。导出前后校验方案版本与分析一致性，缺失或过期结果禁止下载。格式 `1.0` 独立于软件版本，详见 [报告包格式说明](docs/REPORT_PACKAGE_FORMAT.md)。

### v1.2 多选、分组与准确拾取

- 左侧 Shift+点击连续选择，Ctrl+点击增减，Ctrl+Shift 追加区间；顶部一键全选所有对象、相机或障碍物（包括已分组的对象）。
- 多选后右键新建命名分组、移入已有组、移出组；组可折叠、改名、整组选中。组名随项目保存，复制组生成独立分组，支持撤销重做。
- 右键支持复制、粘贴、创建副本、聚焦、批量隐藏/显示、锁定/解锁、删除和更新为参数库版本。每台相机使用自己关联的库型号；锁定对象跳过删除、重新分组和参数更新。
- 三维拾取仅检测实体表面，修复边线的宽容差和透明视锥抢占点击的问题。普通点击选择最前方实体，Alt+点击在重叠对象之间循环选择。
- 可打开旧项目；旧分组自动显示为文件夹。含命名分组的项目建议使用 v1.2 编辑。

### v1.1 方管与 P3 IR

左侧添加「方管桁架」，默认尺寸为 4 × 0.05 × 0.05 m；长度沿局部 X 轴，宽度沿 Y，高度沿 Z。尺寸和旋转可编辑，支持选择、复制粘贴、撤销重做、项目保存，相机吸附和沿管阵列部署。外形按长方体绘制，未建模内部壁厚；默认不参与遮挡，与已有桁架一致。吸附是一次性定位，之后移动结构不会自动带动相机。

在相机库搜索 P3 可找到用户提供的 IR 双目模式，采用确认的每目 2048×1536、120 fps、57.31°×44.58°、4.2±0.21 mm、F2.0 和 144 mm 基线。仅加入 IR 模式，忽略误写的像素总数。厂商名称未提供，来源标为 User supplied；完整供电、接口、滤光补光、传感器、重量与尺寸参数保存在来源记录中。现有库自动追加一次，保留所有编辑与删除记录。

每台双目设备产生左右两个视点，姿态联动；两目独立检查视野、距离、遮挡、Marker 像素和图像边缘，再按实际中心间距参与原有 Jacobian 求解。一台双目设备可以在两目均有效且几何非退化时定位。设备数量与视点数量分别显示；双目预览、像素窗口和报告使用同一套左右目投影。左右目假设相同内参、平行光轴，位置为两目中心，基线沿相机局部水平轴。工作距离未设硬上限，图像点误差 0.1 px、最小 Marker 4 px、无畸变均为可编辑假设；不包含双目标定、匹配、同步和光照误差，不能视为厂商精度或距离承诺。

可打开 v1.0 项目；含新对象或双目参数的项目请使用 v1.1。

## 当前边界

- 本版本使用有版本字段的结构化本地存储，尚未换成 SQLite。清理浏览器/桌面应用数据会清除项目和参数库，请定期导出。分析结果不持久化，重新打开项目后自动计算。
- 已提供安装包与免安装包；尚未提供数字签名、自动升级器或账号同步。跨电脑使用项目和相机库导入导出进行迁移。
- 相机预览使用真实内参投影的线框场景；圆柱在预览中采用外包框。并非带光照、材质和逐像素深度遮挡的照片级图像。
- 热图最多绘制 60,000 个三维网格单元。细采样超过显示上限时，按空间合并相邻单元并铺满对应区域，不再跳点抽样；合并区域显示最低覆盖数、最大 RMS，包含无法解算的点时显示无有效精度。障碍物内部没有采样点的单元不显示，合并单元跨越障碍物边缘时边界为近似显示。**统计始终使用全部有效采样点**。计算上限 1,200,000 个点。边界不能被步长整除时，以等间距单元中心覆盖整个边界，实际间距不超过输入值。
- 灰色热图单元表示零覆盖或不可定位；精度热图深蓝误差小、浅蓝误差大，上限为设定精度阈值的两倍。暂不支持任意手动色标与任意方向剖切面。
- Marker 投影直径按 PRD 针孔近似，畸变仅应用于点投影和 Jacobian；没有像素尺寸经验噪声模型。
- 暂未实现拖动期间的低分辨率自动预计算、完整矩形/笼状桁架编辑器、组级相对约束、连续 Hover 探测、场景 X-Ray/隐藏线模式与多光线 Marker 遮挡模型。
- 安装吸附是一次性位置操作，之后相机姿态独立存在；结构移动不会隐式带动相机。
- 所有误差为理论 1σ 三维位置 RMS，非现场系统精度承诺。标定残差、安装误差、反射、照明、温度、振动与刚体姿态误差未纳入。

## 技术说明

React + TypeScript + Three.js + Zustand；Electron 桌面壳；Vite；Vitest。

```text
src/camera/          独立相机 Repository、参数校验、JSON/CSV
src/project/         项目/方案/对象创建与文件验证
src/simulation/      纯数学、投影/遮挡/精度、Worker
src/renderer/        三维场景、相机姿态、交互、报告共用渲染
src/components/      参数库、属性、预览、诊断、报告
src/i18n.ts          集中维护的中英文语言资源
src/store.ts         项目状态、历史记录与本地保存
electron/            隔离的桌面宿主
```

世界坐标单位为 m，Z 向上。相机局部 +Z 向前、+X 向右、+Y 向图像下方。相机旋转参数为世界 Z 偏航、仰角、光轴滚转；其他物体为 `Rz(yaw) Ry(pitch) Rx(roll)`。协方差采用 `H = Σ JᵀJ / σpx²`，逆矩阵前检查退化与条件数；只对有效观测构建 H。

误差分位数只统计可定位点；覆盖率和 ≤0.3/0.5 mm 达标率以**全部有效采样点**为分母。障碍物内采样点排除，隐藏与参与仿真为独立开关。

## 构建发布包

先使用包含 ReportLab 和 Pillow 的 Python 运行 `scripts/create-release-assets.py` 生成图标和使用说明（使用本机微软雅黑字体），然后运行 `npm run package:win`。`scripts/prepare-release.cjs` 创建独立应用暂存目录，只复制构建产物和桌面宿主，避免带入源码、开发依赖和个人数据。安装包由 NSIS 生成；Electron 运行文件取自本机已安装的精确版本。

默认运行端口为 5178。发布验证可设置 `SCENELAB_USER_DATA_DIR` 为绝对测试目录，并设置 `SCENELAB_PORT` 使用独立端口；普通用户无需配置环境变量。
